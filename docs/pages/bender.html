Object Bender

API, thiết lập Inspector và vòng đời dữ liệu khi uốn nhiều mesh trong một hierarchy.

Object Bender khác Mesh Deform thế nào?

SplineMeshDeform uốn một Source Mesh trên một MeshRenderer. SplineObjectBender uốn toàn bộ các MeshRenderer hợp lệ trong một hierarchy theo cùng trục và cùng khoảng spline; mỗi MeshRenderer nhận một mesh tạm riêng, material của từng Renderer vẫn giữ nguyên. Không gộp các mesh thành một, không giảm draw call chỉ nhờ Bender.

Vì sao ba Capsule có thể chồng lên nhau?

Ở chế độ KeepHierarchy (mặc định), Bender lấy vị trí vertex của từng child trong hệ root. Nếu ba Capsule cùng Mesh và cùng transform, các vertex trùng nhau, nên ba mesh sau khi bend cũng chồng lên nhau — đây là kết quả từ dữ liệu đầu vào, không phải việc ba MeshRenderer bị gộp. Nếu các child được đặt nối đuôi dọc trục Axis thì Bender sẽ giữ khoảng cách đó.

Để tự xếp ba Capsule giống nhau, chọn Layout = Sequential Meshes và chỉnh Part Gap. Bender sẽ dùng thứ tự duyệt MeshRenderer trong Hierarchy để đặt các mesh liên tiếp, không thay đổi transform child hay mesh asset nguồn. Với Capsule thường kéo dài theo Y, chọn Axis = Y; nếu model nhập khẩu có trục dài là Z thì chọn Z.

Sequential Meshes phù hợp các mảnh giống nhau cần nối đầu–đuôi. Không dùng tùy tiện cho model nhiều bộ phận chồng lấp có chủ ý (ví dụ thân tàu, cửa kính, tay nắm), vì chế độ này sẽ dàn mọi mesh thành hàng.

Hierarchy khuyến nghị

Scene
├─ Track              [SplineContainer]  ← ở ngoài TrainModel
└─ TrainModel         [SplineObjectBender]
   ├─ Body             [MeshRenderer, Material A]
   ├─ Window           [MeshRenderer, Material B]
   └─ Decoration       [MeshRenderer, Material C]
  1. Ở Model Importer, bật Allow Data Access cho từng mesh nguồn. Mỗi mesh cần có một primitive/submesh và index.
  2. Chọn TrainModel → thêm SplineObjectBender; đặt Spline = Track.
  3. Đặt Axis trùng trục dài của model gốc (ví dụ Z); chọn khoảng Start/End.
  4. Bật Preview In Editor rồi nhấn Apply Bend trong Inspector. Nhấn Restore để trả mesh gốc.
Không đặt source spline là node con/cháu của Model được uốn. Các knot và tangent handle trong hierarchy đó có thể bị xử lý nhầm.

Public API

Import:

import { SplineObjectBender } from 'db://cocos-splines/splines/Components/SplineObjectBender';
MethodHành vi
rebuild(): voidChụp dữ liệu mesh gốc (nếu chưa chụp), tạo mesh tạm đã uốn cho từng renderer và gán vào renderer.mesh. Gọi thủ công để Apply lại khi rebuildOnChange=false.
restore(): voidĐưa renderer về mesh gốc nếu đang dùng mesh tạm của Bender, hủy mesh tạm, bỏ gizmo. Khóa auto-preview cho đến khi gọi rebuild() rõ ràng; nếu bật Preview lại, có thể cần nhấn Apply Bend.
onDrawGizmosSelected(): voidCallback do Cocos-Gizmos gọi khi node được chọn. Bình thường không cần gọi thủ công.

Ví dụ script Apply / Restore

import { _decorator, Component } from 'cc';
import { SplineObjectBender } from 'db://cocos-splines/splines/Components/SplineObjectBender';
import { SplinePositionMode } from 'db://cocos-splines/splines/Core/SplinePosition';
import { DeformAxis } from 'db://cocos-splines/splines/Components/SplineMeshDeform';
import { BenderLayout } from 'db://cocos-splines/splines/Components/SplineObjectBender';
const { ccclass, property } = _decorator;

@ccclass('BenderControl')
export class BenderControl extends Component {
    @property({ type: SplineObjectBender }) bender: SplineObjectBender | null = null;
    apply(): void {
        if (!this.bender) return;
        this.bender.axis = DeformAxis.Y;
        this.bender.layout = BenderLayout.SequentialMeshes;
        this.bender.partGap = 0.15;
        this.bender.rangeMode = SplinePositionMode.NormalizedDistance;
        this.bender.startProgress = 0;
        this.bender.endProgress = 1;
        this.bender.widthScale = 1.25;
        this.bender.rebuild();
    }
    restore(): void { this.bender?.restore(); }
}

Cách Bender xử lý dữ liệu

  • Đọc MeshRenderer.mesh, POSITION, UV (nếu có), indices; chuyển vertex từ local của từng child về hệ root để lấy vị trí dọc hierarchy.
  • Uốn cả nhóm theo khoảng bắt đầu/kết thúc; tạo normals/tangents cho mesh mới. Mỗi renderer giữ reference material riêng của nó.
  • rebuild() sử dụng hình học gốc đã capture; không uốn chồng lặp trên mesh đã uốn. restore() hoàn trả mesh gốc.
  • Mesh bị bỏ qua nếu không đọc được CPU data hoặc có nhiều primitive; Bender có thể xử lý một phần hierarchy mà không báo lỗi nặng.

Preview, Gizmos và lưu ý

  • previewInEditor=false: không áp dụng uốn trong Scene Editor; nếu đã preview, việc tắt sẽ restore mesh gốc.
  • rebuildOnChange=false: đổi kích thước/khoảng trong Inspector cần nhấn Apply Bend.
  • showMeshGizmos: cần Cocos-Gizmos, chỉ vẽ wireframe khi chọn node, không ảnh hưởng mesh/material.
  • Thay transform của từng child sau khi capture: hãy Restore rồi Apply Bend để capture lại vị trí gốc mới.
  • Không hỗ trợ SkinnedMeshRenderer, multi-submesh, mesh CPU data bị khóa hay blend cùng một hierarchy có mesh source bị phá hủy.
